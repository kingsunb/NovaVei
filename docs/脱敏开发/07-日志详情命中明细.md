# 07 - 日志详情命中明细设计

> **状态: 待实施**（2026-09-15 立项）。需求来源: 日志页已显示"已脱敏"标记与占位符, 但希望详情中能看到哪些内容触发了哪条脱敏规则, 便于审计与规则调优。

---

## 一、需求目标

在日志详情中不仅显示"已脱敏"标记和占位符, 还展示本次请求命中了哪些脱敏规则, 以及对应被替换的内容, 便于定位「哪个内容触发了哪条规则」。不改变请求转发和响应还原逻辑。

---

## 二、现状与关键发现

### 2.1 引擎已产出命中明细, 但未保存

脱敏引擎 `internal/relay/mask/engine.go` 的 `Apply` 返回结构化 `MaskResult`:

```go
type Match struct {
	Label       string // 规则标签, 如 PHONE / EMAIL / SECRET / TERM
	Original    string // 命中原文
	Placeholder string // 替换占位符, 如 {{PHONE_bcdfgh}}
}

type MaskResult struct {
	Masked  string   // 脱敏后的文本
	Mapping *Mapping // 本轮会话映射表(供还原用)
	Matches []Match  // 命中明细  ← 当前被调用方丢弃
}
```

但转发入口 `internal/relay/handler.go:101-119` 的 `applyRequestMask` 只使用 `Masked` 字节与 `Mapping`, 命中明细被丢弃:

```go
masked, mapping, mErr := applyRequestMask(raw.Body, sessionKey, g.RelayConfig.MaskEnabled)
// ...
if maskMapping != nil {
	streamRestorer = mask.NewStreamRestorer(maskMapping)
	request.Masked = true   // 仅有布尔标记, 没有命中明细
}
request.updateBody(string(masked))
```

### 2.2 日志请求体已是占位符版本

`RequestState.updateBody` 把状态中的请求体替换为脱敏后版本(凭据安全红线, 文档 04 §五), `/api/v1/log/:id/request-body`(`internal/server/handlers/log.go` `getRequestBody`)返回的正是该脱敏后文本。因此日志详情已经能看到 `{{PHONE_xxx}}` 占位符, 唯独缺少"哪个占位符来自哪条规则、原文是什么"的对应关系。

### 2.3 命中明细的现成形状

`/api/v1/mask/test` 管理接口(`internal/server/handlers/mask.go`)已返回命中明细, 形状可完全复用:

```go
type maskTestMatch struct {
	Label       string `json:"label"`
	Original    string `json:"original"`
	Placeholder string `json:"placeholder"`
}
```

### 2.4 前端展示点

- 实时日志详情: `web-next/src/pages/Logs.tsx` 的 `TraceSheet`(约 L668), 头部"已脱敏"标记在 L817, 左侧"请求体"面板在 L833-861。
- 错误日志展开区: 同文件 `ErrorLogRow`(约 L580-638), 展示 `request_body` / `err_detail`。

### 2.5 持久化错误日志无命中记录

`model.ErrorLog`(`internal/model/error_log.go`)只保存脱敏后的 `RequestBody`, 无命中字段; `recordErrorLog`(`handler.go:1071`)入队时不带命中明细。

---

## 三、实施方案

### 3.1 后端: 命中明细进请求状态

1. 扩展 `applyRequestMask`(`internal/relay/mask_integration.go:27`), 从返回 `(masked, mapping, error)` 调整为同时返回 `[]mask.Match`(或返回 `mask.MaskResult` 的必要部分)。开关关闭、未命中时返回空明细, 零额外展示数据。
2. `RequestState` 增加仅在脱敏发生时输出的字段(建议 JSON 名 `mask_matches`, 元素形状与 `maskTestMatch` 一致)。
3. `handler.go` 应用脱敏后, 把命中明细复制到 `request.MaskMatches`, 并发布一次请求状态(`publishRequestLocked` 路径), 使已打开的日志详情实时收到命中信息。
4. **不变项**: 不把原始请求体写回 body; 不改变发往上游的内容; 空会话/请求级 mapping、跨轮占位符复用、`StreamRestorer` 逻辑全部现状保留。命中明细只属于当前请求这一次 `Apply` 的结果, 按引擎返回顺序(已按唯一原文去重保序)原样使用。

### 3.2 后端: 序列化与接口

1. 更新 `RequestState.MarshalJSON`(`internal/relay/state.go:192`)的自定义序列化路径, 把 `mask_matches` 纳入对外 JSON, 避免因自定义 marshal 遗漏新字段。
2. `/api/v1/log/:id/request-body` 保持返回脱敏后请求体不变; **不新增任何恢复明文的接口**, 命中明细随状态流下发而非挂在请求体接口上。
3. 持久化错误日志(可选但建议一致):
   - `model.ErrorLog` 增加 `MaskMatches` TEXT 字段(JSON 序列化存储)。
   - `recordErrorLog` 在入队时携带命中明细; 旧记录该字段为空数组, 天然兼容, 无需迁移。
   - 注意 `errCompleteLogCount` 配额: 完整请求体每类只保留前 3 条, 命中明细的保留策略需与之对齐(建议仅在保留完整请求体的条目上附带命中明细, 控制落盘量)。

### 3.3 前端: 日志详情展示

1. 更新前端 `RequestState` 类型(`web-next/src/lib/types.ts`), 增加 `mask_matches?: { label: string; original: string; placeholder: string }[]`。
2. 在 `TraceSheet` 左侧"请求体"面板内增加"脱敏命中"区域(位于请求体上方或下方):
   - 每条一行: 规则标签 Pill(如 PHONE / EMAIL / SECRET / TERM)、占位符、被替换的原文。
   - 无命中时不渲染该区域(与"已脱敏"标记互证: 标记存在但无明细 = 旧版本进程 / 开关后关特例)。
   - 原文为敏感内容: 默认视觉弱化(等宽小字 + 局部模糊或需点击展开), 但允许管理员查看; 标注"仅本请求命中明细", 避免与响应正文混淆。
3. 请求体展示保持不变(占位符版本); 错误日志 `ErrorLogRow` 展开区复用同一展示组件, 新增"触发规则"小节(读取持久化的 `mask_matches`)。

### 3.4 测试

1. **引擎/状态序列化**: 命中 PHONE + 自定义 TERM 后, `RequestState` JSON 含正确的 label/original/placeholder; 无命中与开关关闭时无该字段或为空数组。
2. **handler 链路**: 发脱敏请求 → 状态流的 `mask_matches` 与请求体中的占位符一致; 转发上行 body 与响应还原不受影响。
3. **错误日志持久化**(若做): 新记录保留命中明细; 旧记录无字段可正常读取; 命中明细不突破请求体配额策略。

## 四、安全边界(凭据红线, 文档 04 §五)

| 项目 | 边界 |
|---|---|
| 命中原文可见范围 | 仅已通过管理员鉴权的日志详情/错误日志; 不落对话留存之外的额外明文 |
| 上游请求 | 不变, 仍是占位符版本 |
| 请求体接口 | 仍返回脱敏后文本, 不新增明文恢复接口 |
| 错误日志落盘 | 命中原文属敏感数据, 沿用现有截断与配额策略; 如需进一步收敛, 可改为只存 `label + placeholder`(不存原文) |
| 会话映射表 | 仍为内存 + TTL, 命中明细的持久化不改变还原路径的攻击面 |

## 六、风险与对策

1. **敏感原文重新可见**: 命中明细含原文, 与"日志只存脱敏后内容"的红线有张力。对策: 仅管理员面可见、错误日志可只存 label+placeholder、前端默认弱化展示。
2. **SSE 载荷增大**: 命中明细通常几十条以内, 体积可控; 进程内状态生命周期与报文预览一致, 终态后按 `maxFinished`(200) 裁剪。
3. **旧版本进程/旧记录兼容**: 字段缺省为空, 前端与反序列化均按可选处理。
